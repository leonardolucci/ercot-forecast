# Rules for changing this repository

Read before changing anything. These rules hold for people and agents alike:
a change that breaks one of them is wrong even if it works.

Context lives in `docs/`: `STATE.md` (where the project stands),
`STRUCTURE.md` (where files go) and `ROADMAP.md` (phases).

## 1. Order of work

    data -> features -> baseline -> model -> evaluation -> decision

Each stage starts only after the previous one has a written, verifiable
result. No machine-learning model before the seasonal naive and LEAR
baselines are measured, and a model is kept only if it beats the previous
one under the same backtest protocol.

## 2. Point-in-time discipline

- Every record carries an `available_at` timestamp: the moment the
  information became available. A record without one does not enter the
  system.
- No feature may read a record whose `available_at` is later than the
  moment of prediction.
- An automated temporal leakage test will enforce this in CI. Never skip,
  weaken or work around it.
- Backtests are rolling, with retraining. Never a random split.
- A result that looks too good is a leakage suspect until proven otherwise.

## 3. Import direction

`src/ercot_forecast/` has one subpackage per stage, in this order:

    ingest -> features -> models -> evaluation -> decision

A module may import from its own subpackage or from any subpackage to its
left, never from one to its right: `features` may import `ingest`, but
`ingest` may never import `features`. If code needs something from its
right, an import is not missing: a function is in the wrong place.

This list is not the order of work in section 1: baselines and ML models
both live in `models/`.

## 4. Source vs. derived

- Source, version-controlled: `src/`, `scripts/`, `tests/`, `config/`,
  `docs/`, `notebooks/` and the root files. If deleting a file means it
  cannot be regenerated by running something in the repository, it is
  source.
- Derived, Git-ignored: `data/` and `artifacts/`. Never created by hand:
  the function that writes to them creates the folder it needs, when it
  writes, never at module level.
- `data/raw/` is append-only and may be impossible to download again:
  never edit, overwrite or delete a raw file.
- `notebooks/` is a laboratory: nothing imports from it, and no logic
  counts until it lives in `src/`.

## 5. Never commit

- Anything under `data/` or `artifacts/`.
- Secrets. `.env` holds the values and is ignored; `.env.example` shows
  only the variable names.
- Machine-specific state: virtual environments, caches, absolute paths.

## 6. Conventions

- Environment: uv and Python 3.13. Dependencies change only through
  `pyproject.toml` and `uv.lock`, committed together.
- Commits: Conventional Commits (`feat:`, `fix:`, `docs:`, `build:`,
  `chore:` ...) in the imperative mood, one logical change per commit.
- `main` changes only through pull requests.
- All project text is written in English.
